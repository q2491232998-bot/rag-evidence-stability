# Preserving Serial Evidence in Batched Retrieval-Augmented Generation with Selective Rescoring

Reproducibility materials for the manuscript. This directory is self-contained for auditing the released numerical results. Its scope differs from the earlier repository release at the project root.

**Start here.** From this directory, run `python3 src/verify_release.py` (Python standard library). It checks 981 primary ledger rows using source rows/fields, 96 derived extension rows using query repeats, 628 second-device rows using query, cross-device and calibration data, and the individual calibration score pairs. Identical ledger keys may occur in different cells of the original 4090 ledger; counts are rows, not unique claims. All three evidence ledgers and the protocol-constant table are in `paper/eswa_selective_rescoring_v1/generated/`. Original unrounded values and manuscript display strings are separate. Results are not new GPU measurements.

| Location | Contents |
|---|---|
| `research/`, `configs/` | Development, prospective and extension protocols; original decision to continue after the failed development criterion; model revisions, reader settings and evaluation rules. |
| `src/` | Candidate preparation, model scoring, packing, calibration, metrics, analysis and audit code. `verify_release.py` is the public entry point. The earlier manuscript build script documents the original 3090 Ti pipeline; do not use it to overwrite this release. |
| `results/eswa_gate_20261110_v1/` | Stage 0 ID/hash/selection audit, development grids, selected results and diagnostics of five residual cases. The older 128 questions were subsequently development data. |

| `results/eswa_extension_20261111_v1/` | Other batch sizes, random grouping, precision comparison, band, invalid timing observations and timing occupancy. These samples were reused. |
| `results/rtx4090_validation/` | Fresh-sample evaluation, per-repeat/per-question exports, sample IDs/splits, two band configurations, same-question cross-device comparison, and calibration/freeze metadata. |

**Reading the files.** Indices are the permanent, zero-based candidate indices within a question. The order of selected indices matters. An empty metric is unavailable or unevaluated, not zero. Use the question ID, dataset, model, method, batch size and repeat (and seed when applicable) as a compound key. “Serial” refers to the same-device native BF16 implementation unless the file explicitly specifies FP32 or the other GPU. Compare times only to the reference session identified by that file; the older extension reused the stage-2 serial timing. Sampling of external GPU processes cannot exclude activity between samples.

**What was withheld.** The package includes IDs, index selections, scores, hashes, metrics and timing, not source questions, paper/passage text, reader prompts instantiated with benchmark text, ground-truth or generated answer strings, model weights, retrieval indexes, or credentials. Hashes of raw and normalized answers allow equality checks without reconstructing text. Original full CSVs retained raw strings, while the public exports omit them. Gold-recall and answer-F1 values can be aggregated from these exports; recomputation from annotations requires the original licensed inputs. The original freeze receipts identify the historic run, not hashes of redacted files. GPU UUIDs in public copies are replaced with a placeholder; retain original freeze receipts for provenance and configure a fresh local freeze for a new run.

**Fresh execution.** Obtain [QASPER](https://allenai.org/data/qasper), [HotpotQA](https://hotpotqa.github.io/), the relevant retrieval corpus/indexes and [Qwen3-Reranker-0.6B](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B), [bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3) and [Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B) under their own terms. Dataset hashes, URLs and model revisions are in the acquisition records and configurations. Full raw-score generation also needs the Linux/CUDA environment, retrieval indexes and historical exclusion inputs described in the frozen protocols. This is not a one-command recreation of those external assets. `src/export_calibration.py INPUT_DIR OUTPUT_DIR` regenerates the candidate pairs and witnesses from the separately retained, hash-checked 4090 raw calibration logs. No paper PDF or signed declarations are included.
